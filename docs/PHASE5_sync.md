# Фаза 5 — Синхронизация вкладок без бэкенда

Ты работаешь по `CLAUDE.md` в корне репозитория. Он важнее этого документа.
Старт — по §6 контракта: `scripts/boot.sh` → `docs/BOOT.md` → пересказ в 5 строках → ждать подтверждения.

## Контекст (зачем фаза)

Хост и гость полностью работают, но каждый в своей вкладке и без сохранения (фазы 2–4).
Фаза делает «3 вкладки = 3 телефона» и демо на одном экране. Потребитель — демо для жюри и будущая замена на Supabase Realtime за тем же интерфейсом.

## Что делаем

Интерфейс `SessionTransport` (`load`, `save`, `subscribe`), реализация на `localStorage` + `BroadcastChannel("splitcheck:<id>")`, подключение стора, `?as=guest`, dev-кнопка «Symuluj gości» при `?dev=1`. Источник истины — `docs/SPEC.md`, раздел «Синхронизация без бэкенда».

## Критерий «работает» (формулируем ДО кода)

1. `npm test; echo exit=$?` → `exit=0`; тесты транспорта с внедрёнными in-memory хранилищем и каналом: `save` → `load` возвращает то же; `save` в одном экземпляре → `subscribe` второго получает сессию; отписка работает.
2. `npx tsc --noEmit; echo exit=$?` → `exit=0`; `npm run build; echo exit=$?` → `exit=0`.
3. Ручная: F5 на `/s/<id>` — сессия, клеймы и имена на месте.
4. Ручная: вкладка хоста + 2 вкладки `/s/<id>?as=guest` → тап в любой виден в остальных мгновенно; «Twoja część» у всех трёх в сумме = итог чека.
5. Ручная: `/s/<id>?dev=1` → «Symuluj gości» → появляются Ania, Kuba, Ola, тапают случайные позиции с задержкой 400–900 мс; прогресс растёт, dev-проверка инварианта молчит.
6. Ручная: `/s/<несуществующий>` → понятное пустое состояние, без падения.

## Стек (не расширять)

- Только браузерные `localStorage`, `sessionStorage`, `BroadcastChannel`; `zustand`, `nanoid`.
- Никаких новых пакетов без строки в `docs/DECISIONS.md` и проверки, что версия реально встала (`npm i` → что записалось в манифест).

## Структура (новое и изменяемое)

```
src/lib/transport/types.ts      # SessionTransport
src/lib/transport/broadcast.ts  # localStorage + BroadcastChannel
```

Правило: UI и стор знают только `SessionTransport`, не `BroadcastChannel`. Проверка: `grep -rln "BroadcastChannel" src --exclude-dir=transport; echo exit=$?` → `exit=1`.

## Риски и решения фазы (решить в шаге 1, записать в DECISIONS.md)

- **Кто я во второй вкладке (решено 2026-10-31, см. DECISIONS).** `localStorage` общий для всех вкладок одного origin, поэтому `splitcheck:me:<id>` из SPEC сделал бы вторую вкладку хостом. Решение: «кто я» — сначала `sessionStorage` вкладки, потом `localStorage`; `?as=guest` создаёт участника и пишет его только в `sessionStorage`.
- **Конфликты записи.** Дефолт: рассылаем снимок сессии целиком с `version`, last-write-wins. Риск: одновременные тапы в разных вкладках в пределах миллисекунд потеряют один. Для демо (симуляция идёт из одной вкладки) приемлемо; операции/CRDT → `NOT_NOW.md`.
- `[предположение]` `BroadcastChannel` не доставляет сообщение вкладке-отправителю — проверить: тест или `console.log` в двух вкладках.

## Что НЕ делать

- Supabase, WebSocket, любой сервер → `NOT_NOW.md` (уже есть).
- Синхронизацию между разными реальными телефонами — честно не поддерживается до бэкенда.
- Автоудаление сессий через 24 часа → `NOT_NOW.md`.
