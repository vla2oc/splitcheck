# agent-kit — стартовый набор для работы с Claude Code в паре

Кладёшь в новый репозиторий до первой строки кода. Даёт агенту: **контракт** (как работать), **память** (что переживает `/clear`), **потолки** (что не даёт памяти разрастись) и **проверки, которые падают, а не напоминают**.

Собран 2026-09-20 из системы проекта `convoymind` (v1) с исправлением того, что там просело за две недели. Каждое отклонение от v1 — в таблице внизу; можно отклонить построчно.

## Файлы

```
CLAUDE.md                 контракт: роль, три состояния знания, порядок работы, потолки. Claude Code грузит его сам
.claude/settings.json     allowlist команд + два хука: SessionStart (boot) и Stop (проверка потолков)
.githooks/pre-commit      секреты; потолки docs; «код без STATE.md не коммитится»
.gitignore                docs/BOOT.md, .env
docs/
  STATE.md                чекпоинт: цель, сделано (текущая фаза), сейчас, следующий шаг, вопросы, [предположение]. ≤ 80 строк
  DECISIONS.md            решения: `дата | решение | причина`, ≤ 200 символов. Единственный источник
  NOT_NOW.md              что осознанно не делаем. «Знаем и отложили» ≠ «не подумали»
  BOOT.md                 генерируется; единственное, что агент читает при старте. ≤ 4096 байт. Не в git
  PHASE_TEMPLATE.md       бриф фазы: критерий «работает» ДО кода, стек «не расширять», шаги
  CONTRACT_TEMPLATE.md    передача между агентами с чистым контекстом
  log/                    архив; при старте не читается
scripts/
  setup.sh                один раз после копирования
  boot.sh                 STATE целиком + 5 последних решений + NOT_NOW → docs/BOOT.md; при превышении — предупреждение первой строкой
  check-docs.sh           все потолки; exit 1 = нарушение
  stop-hook.sh            обёртка check-docs для Stop-хука Claude Code
```

## Как это работает: одна сессия

1. **Старт** (или `/clear`). SessionStart-хук запускает `boot.sh` и печатает `BOOT.md` в контекст. Контракт §6 дублирует это правилом: «прочитай BOOT.md, перескажи в 5 строках, жди подтверждения».
2. Ты подтверждаешь пересказ → даёшь задачу → агент пересказывает её в 3 строках → план → подтверждение.
3. **Один шаг**: диф → команда проверки → реальный вывод.
4. **Чекпоинт**: агент перезаписывает `STATE.md`; решения — строкой в `DECISIONS.md`; отложенное — в `NOT_NOW.md`.
5. **Коммит.** `pre-commit` проверяет секреты, потолки и что `STATE.md` в индексе. Красный — чинит, не обходит.
6. **Конец хода.** Stop-хук гоняет `check-docs.sh`; при нарушении агент не может закончить ход — получает список и правит.
7. Сессия стала длинной → `/clear` → п. 1. Цена рестарта — `BOOT.md` (≤ 4 КБ) + `CLAUDE.md` (≤ 8 КБ), а не вся история.

## Как агент помнит

У модели нет памяти между сессиями. «Помнит» она ровно то, что положили в контекст при старте. Поэтому память — четыре слоя файлов с разной судьбой:

| Слой | Где | Судьба | Читается при старте |
|---|---|---|---|
| Правила | `CLAUDE.md` | постоянный, меняется редко | да, автоматически |
| Снимок | `docs/BOOT.md` | генерируется каждый старт | да — единственное, что читается по правилу |
| Истина | `STATE.md`, `DECISIONS.md`, `NOT_NOW.md` | перезапись / дописывание, в git | через BOOT, частично |
| Архив | `docs/log/`, git-история, фазовые отчёты | только дописывается | нет; по ссылке, когда нужно |

**Не используется, и это решение:** авто-память Claude Code (`~/.claude/projects/<repo>/memory/`). Она живёт на одной машине, не версионируется и невидима второму агенту и человеку. Файлы в репо видны всем, диффятся, переезжают с клоном.

**Почему в v1 сломалось.** `STATE.md` назывался чекпоинтом, но дописывать его никто не запрещал: за три коммита он вырос 78 → 93 → 105 КБ и стал журналом на 33 заголовка. Правило рестарта «прочитай три файла» стоило ~192 КБ на каждый `/clear`. Файл, созданный против потери контекста, стал её главным потребителем. Лечение — не «пиши короче», а потолок с числом и скрипт, который его проверяет.

## Как агент принимает решения

- **Три состояния знания** (§1): знаю / предполагаю / не знаю. Действовать можно только из «знаю» = прочитал в этой сессии.
- **Маркеры** (§7): `[проверено]` с источником, `[предположение]` с командой проверки, `[не знаю]` с вопросом. Без маркера = предположение.
- **Вопросы** (§3): ≤ 3 за раз, к каждому дефолт. Мелкое и обратимое — решает сам, строка в `DECISIONS.md`. Крупное — ждёт ответа.
- **Отложенное** → `NOT_NOW.md`. Без этого агент предлагает одно и то же по кругу.
- **Критерий «работает»** — до кода, в фазовом брифе, как наблюдаемое поведение. «Готово» = показан реальный вывод.
- **Между фазами** — `CONTRACT_*.md`: следующий агент стартует с чистым контекстом и читает контракт, а не исходники предыдущей фазы.

## Как контекст деградирует и что с этим делает набор

Агент не замечает потерю контекста изнутри; просьба «сообщи, если потерял» помогает, но не гарантирует. Поэтому защита структурная:

- маленький BOOT → дешёвый `/clear` после любого шага;
- коммит на шаг → git-лог как бесплатная таймлиния; BOOT показывает последний коммит и число незакоммиченных файлов (симптом «не помню, применён ли диф»);
- один источник истины по решениям (в v1 их было два — `## Решения` в STATE и DECISIONS.md);
- проверки, а не напоминания: pre-commit и Stop-хук падают.

## Где стреляют проверки

| Когда | Что | Чем |
|---|---|---|
| Старт сессии | генерация BOOT, потолок 4096 байт; файл печатается в контекст всегда, при превышении — с предупреждением первой строкой | `boot.sh` (SessionStart-хук) |
| Любая проверка | общий бюджет старта `CLAUDE.md` + `BOOT.md` ≤ 12288 байт | `check-docs.sh` |
| Конец каждого хода агента | все потолки; при нарушении ход не завершается | `stop-hook.sh` → `check-docs.sh` |
| `git commit` | секреты; потолки; код без STATE.md | `.githooks/pre-commit` |
| Вручную / CI | всё то же | `scripts/check-docs.sh` |

## Установка в новый проект

```sh
rsync -a --exclude .git --exclude README.md --exclude docs/BOOT.md ~/work/develop/agent-kit/ <новый-проект>/
cd <новый-проект>
scripts/setup.sh        # права, core.hooksPath, первая проверка, первый BOOT
```

Дальше: «Цель MVP» в `docs/STATE.md` → `docs/PHASE1_<имя>.md` по шаблону → первый коммит. Примеры решений в `DECISIONS.md` оставить (они про набор и верны для любого проекта) или очистить. В `.claude/settings.json` добавить свои команды тестов в allowlist.

Настройка под себя: числа потолков — в `scripts/check-docs.sh` и `scripts/boot.sh` (+ строка в DECISIONS); формулировки — в `CLAUDE.md` (потолок 8 КБ, проверяется).

## Отклонения от v1 (convoymind) — можно отклонить построчно

| # | Было в v1 | Стало | Почему |
|---|---|---|---|
| 1 | STATE.md без потолка, «Сделано» копится по всем фазам | ≤ 80 строк, ≤ 6 «##», «Сделано» только текущей фазы и новое сверху, остальное в `docs/log/` | 105 КБ за 3 коммита; порядок в «Сделано» был 09-19, 09-06, шаги 1,2,3,4,5,8,7,6 |
| 2 | «решение одной строкой» | `дата \| решение \| причина`, ≤ 200 символов, проверяется | 582 символа на строку в среднем — правило без числа уехало |
| 3 | `## Решения` в STATE **и** DECISIONS.md | только DECISIONS.md | два источника разойдутся |
| 4 | старт = «прочитай STATE, DECISIONS, NOT_NOW» (~192 КБ) | старт = `BOOT.md` (≤ 4 КБ, генерируется) | половина окна уходила до первого вопроса |
| 5 | без маркера = `[проверено]` | без маркера = `[предположение]` | безопасный дефолт — слабое утверждение |
| 6 | pre-commit только на секреты, в `scripts/hooks` + симлинк руками | `.githooks/` + `core.hooksPath`; + потолки; + «код без STATE.md» | переезжает с клоном; проверка вместо напоминания |
| 7 | коммит «когда накопится» (3 за 2 недели) | один шаг = один коммит | иначе pre-commit не стреляет |
| 8 | без `.claude/` | allowlist + SessionStart/Stop-хуки | меньше промптов; ход не завершается с нарушением |
| 9 | шаблон чекпоинта внутри CLAUDE.md | в самом `docs/STATE.md` | контракт короче; шаблон там, где заполняют |
| 10 | NOT_NOW без потолка | ≤ 200 символов на строку | иначе не влезет в BOOT |
| 11 | CLAUDE.md 7,5 КБ без потолка | потолок 8 192 байт, проверяется | чтобы контракт не пошёл дорогой STATE |
| 13 | бюджет старта не измерялся | `CLAUDE.md` + `BOOT.md` ≤ 12 288 байт, проверяется. Ты называл 5 КБ: контракт один весит 7,6 — резать его ради числа я не стал, число в одной строке `check-docs.sh` | владелец решает, что дороже: правила или байты |
| 12 | «символы» считались на глаз | `wc -m` под UTF-8; байты — `wc -c` | на macOS `awk length` считает байты: «200 символов» = ~110 кириллических |

**Не тронуто** (это ядро v1): PHASE-брифы (критерий до кода, стек не расширять, шаг = диф + команда + вывод), контракт между фазами, маркеры, `NOT_NOW` как идея, ловушка `tsc | tail` (в `PHASE_TEMPLATE.md`).

## Что в наборе помечено `[предположение]` — проверить на первой сессии

1. stdout SessionStart-хука попадает в контекст агента. Проверка: новая сессия → «что написано в BOOT?». Если нет — §6 всё равно заставит агента прочитать `BOOT.md` руками; хук тогда только генерирует файл.
2. Поле `stop_hook_active` в stdin Stop-хука (защита от цикла «заблокировали → снова стоп»). Если поля нет, защита не сработает; проверка: `claude --debug`.
3. `$CLAUDE_PROJECT_DIR` в хуках; есть фолбэк на текущую папку.
4. Если `.claude/` появился в папке после старта сессии — хуки подхватятся после `/hooks` или перезапуска (из документации `update-config`).

Схема `settings.json` и имена событий `SessionStart`/`Stop`, поле `decision: "block"` — `[проверено]` по схеме настроек Claude Code 2026-09-20.

## Самопроверка набора (2026-09-20, реальный вывод)

- `scripts/setup.sh` → `check-docs: ok`, `boot: docs/BOOT.md — 2624 байт (потолок 4096)`.
- Стартовое чтение = `CLAUDE.md` 7698 + `BOOT.md` 2624 = **10 322 байт** (потолок 12 288; v1 — ~200 КБ).
- Строка SessionStart-хука pipe-тестом: в норме → BOOT в stdout; при раздутом NOT_NOW (5135 байт) → BOOT всё равно в stdout, первой строкой «ПРЕВЫШЕН ПОТОЛОК», диагностика в stderr.
- Негативные тесты, все exit 1: STATE 81 строка; STATE строка 312 символов; DECISIONS 207 символов; строка не по формату; «Сделано» старое сверху; BOOT > 4096 (и boot.sh, и check-docs через общий бюджет); секрет в индексе; код без STATE.md. Stop-хук при нарушении → `{"decision":"block",…}`, при `stop_hook_active` → пусто. Правка инфраструктуры набора без STATE.md → pre-commit пропускает.
