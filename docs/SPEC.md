# SplitCheck — план реализации фронтенда (MVP для хакатона)

## Контекст для агента

Делаем мобильное веб-приложение для деления счёта в ресторане. Хост фоткает чек, получает ссылку/QR, друзья открывают ссылку без регистрации, тапают свои позиции и видят, сколько должны хосту (перевод через BLIK).

**Сейчас делаем только фронтенд.** Нет бэкенда, нет LLM. Распознавание чека — мок с фикстурой. Синхронизация между участниками — через вкладки браузера (BroadcastChannel). Цель — увидеть и потрогать интерфейс.

Критерии жюри, под которые всё подчинено:

1. **Design is how it works** — пользователь понимает, что делать, без инструкций.
2. **Minimalism** — одна функция, сделанная идеально. Никаких лишних фич.
3. **Sophisticated simplicity** — вся сложность (деление, округление, синхронизация) под капотом.

Язык интерфейса: **польский**. Валюта: PLN, формат `pl-PL` (`214,50 zł`).

## Продуктовые правила (не менять)

- Хост: фото → «Udostępnij». Два тапа.
- Гость: открыл ссылку → сразу видит чек → тапает своё → видит сумму. Имя спрашиваем **только при первом тапе**, не на входе.
- Одно правило деления: тапнул строку — она твоя; тапнули несколько — делится поровну; никто не взял — остаётся на хосте.
- Позиции с количеством («3× Piwo») всегда развёрнуты в отдельные строки. Логики количества в UI нет.
- Сервис/чаевые распределяются пропорционально доле каждого. Отдельного экрана нет.
- Нет статусов сессии, нет кнопки «закрыть», нет draft. Суммы всегда живые. Хост может поправить цену в любой момент.
- Видно, кто взял каждую позицию (аватары с инициалами).
- Всегда виден прогресс: «Rozdzielono X / Y zł».

## Чего НЕ делать

Регистрация, логин, история, группы, настройки, светлая тема, онбординг, туториалы, отметки «zapłaciłem», графики, режим «телефон по кругу», LLM, бэкенд, i18n. Если хочется добавить экран — не добавлять.

## Стек

- Next.js (последняя стабильная, App Router) + TypeScript (strict)
- Tailwind CSS (токены через CSS-переменные)
- `motion` (бывший Framer Motion, импорт из `motion/react`) — все анимации на springs

- `qrcode.react` — QR
- `lucide-react` — иконки
- `nanoid` — id сессий и участников
- Vitest — тесты для логики деления

Шрифты через `next/font/google`:

- **Instrument Sans** — весь UI (тренд «bouba grotesk»: мягкий гуманистичный гротеск, характерный для AI-продуктов 2026).
- **Geist Mono** — все суммы и цены, `tabular-nums`, чтобы цифры не прыгали при анимации.
- Опционально **Instrument Serif** italic — только одно слово в заголовке главного экрана. Больше нигде.

### Отступы и формы

- Mobile-first, дизайн под 390px, максимум ширины контента 440px по центру на десктопе
- Радиусы: карточки 20px, строки 16px, кнопки 999px (pill)
- Тач-зоны ≥ 48px

### Springs (`lib/motion.ts`)

```ts
export const spring = {
  snappy: { type: "spring", stiffness: 500, damping: 32 }, // тапы, тогглы, нажатия
  smooth: { type: "spring", stiffness: 260, damping: 28 }, // bottom sheets, layout
  bouncy: { type: "spring", stiffness: 420, damping: 18 }, // появление аватаров, галочка
} as const;

export const numberSpring = { stiffness: 120, damping: 20 }; // useSpring для сумм
```

- Обернуть приложение в `<MotionConfig reducedMotion="user">`.
- Анимировать только `transform` и `opacity`.
- Нажатие любой кнопки: `whileTap={{ scale: 0.96 }}` со `snappy`.
- Суммы анимируются через `useSpring` + `useTransform` и форматирование в `pl-PL`.

## Данные

### Контракт распознавания (под будущий LLM)

```ts
// lib/receipt/types.ts
export type ParsedReceipt = {
  merchant?: string;
  currency: "PLN";
  items: { name: string; priceGrosze: number }[]; // количество уже развёрнуто в строки
  serviceGrosze: number; // сервис/чаевые, 0 если нет
  totalGrosze: number;
};

export interface ReceiptParser {
  parse(file: File): Promise<ParsedReceipt>;
}
```

Сейчас: `mockReceiptParser` — ждёт ~1800 мс и возвращает фикстуру. Позже он заменяется на вызов `/api/parse-receipt` с тем же типом, UI не меняется.

**Все деньги — целые гроши (integer).** Никаких float.

### Фикстура (`lib/receipt/fixture.ts`)

Реалистичный польский ресторан, ~8–10 строк, например:
Pizza Margherita 32,00 · Burger klasyczny 38,00 · Frytki 12,00 · Piwo Żywiec 0,5l 14,00 (×3 отдельные строки) · Coca-Cola 0,33l 9,00 · Lemoniada 14,00 · Tiramisu 18,00 · Serwis 10%.
`totalGrosze` должен сходиться с суммой.

### Состояние сессии

```ts
type Participant = { id: string; name: string; color: string; isHost: boolean };
type Item = { id: string; name: string; priceGrosze: number };

type Session = {
  id: string;
  merchant?: string;
  items: Item[];
  serviceGrosze: number;
  participants: Participant[];
  claims: Record<string /* itemId */, string[] /* participantIds */>;
  blikPhone?: string;
  createdAt: number;
};
```

Zustand-стор с действиями: `createSession`, `toggleClaim`, `addParticipant`, `renameParticipant`, `updateItemPrice`, `setBlikPhone`.

Кто я на этом устройстве: `localStorage["splitcheck:me:<sessionId>"] = participantId`. Хост помечается при создании сессии.

### Логика деления (`lib/split.ts`) — чистые функции + тесты

- `shareOf(session, participantId): number` — гроши.
- Позиция, взятая n людьми: каждый получает `floor(price / n)`, остаток грошей раздаётся по одному первым по порядку входа (largest remainder). Сумма долей по позиции = цена позиции, всегда.
- Сервис распределяется пропорционально долям тем же способом.
- Невзятые позиции (и их часть сервиса) добавляются к доле хоста.
- `allocated(session)` — сколько уже распределено (без учёта «невзятое → хосту»), для прогресс-бара.
- **Инвариант (тест):** сумма долей всех участников === `total` при любой комбинации клеймов.

Тесты в Vitest: одна позиция на троих (неделимые гроши), пустые клеймы, всё взято, сервис 0 и не 0, хост ничего не тапал.

## Экраны

### 1. Главная `/`

- Заголовок: «Podziel rachunek _w 10 sekund_» (одно слово можно Instrument Serif italic).
- Подзаголовок: «Bez rejestracji. Bez aplikacji.»
- Одна большая pill-кнопка Vista: иконка камеры + «Zrób zdjęcie paragonu» (`<input type="file" accept="image/*" capture="environment">`).
- Под ней текстовая ссылка «Wybierz z galerii» (тот же input без `capture`).
- Анимация входа: заголовок и кнопка появляются с `smooth` и stagger 60 мс.

### 2. Сканирование (состояние на главной, не отдельный роут)

- Выбранное фото показывается в карточке (`URL.createObjectURL`).
- Поверх фото горизонтальная светящаяся линия Vista ездит сверху вниз (scan).
- Текст: «Czytam paragon…».
- Когда парсер вернул данные: создаётся сессия, переход на `/s/[id]`. Карточка фото морфится в список через `layoutId`, строки «падают» по одной (stagger 40 мс, `smooth`).

### 3. Сессия `/s/[id]` — общий экран для хоста и гостей

**Шапка**

- Название места (если есть) и «Paragon · 214,50 zł».
- Прогресс-бар Vista: «Rozdzielono 160,00 / 214,50 zł». Ширина анимируется spring.

**Список позиций**

- Строка: название, цена (mono), справа стопка аватаров тех, кто взял.
- Тап по строке → toggle claim для меня:
  - фон строки плавно в `--vista-soft`, бордер Vista;
  - галочка появляется с `bouncy`;
  - мой аватар «вылетает» в стопку с `bouncy`;
  - `navigator.vibrate?.(10)`.
- Если позицию взяли ≥2 человек — маленький бейдж «÷2».
- Хост видит у строк иконку карандаша → инлайн-редактирование цены (на случай ошибки распознавания).

**Имя при первом тапе**

- Bottom sheet (`smooth`, перетаскиваемый вниз для закрытия): «Jak masz na imię?», одно поле, кнопка «Gotowe». Enter = готово.
- Тап, который вызвал шит, применяется после ввода имени.

**Нижняя панель (sticky)**

- «Twoja część» + сумма (36–40px, mono, анимированная через `useSpring`).
- Для гостя: если у хоста есть BLIK — pill-кнопка «Skopiuj numer BLIK · 600 123 456», по тапу тост «Skopiowano».
- Для хоста: pill-кнопка Vista «Udostępnij».

**Шит «Udostępnij» (хост)**

- Большой QR со ссылкой на сессию (светлые модули на `--surface-2` или белая плашка — проверить, что сканируется).
- Кнопки «Kopiuj link» и «Udostępnij…» (`navigator.share`, fallback на копирование).
- Поле «Numer do BLIK (opcjonalnie)», значение запоминается в `localStorage` для следующих сессий.

**Блок «Kto ile» (хост, под списком или во втором табе-переключателе)**

- Список участников: аватар, имя, сумма.
- Отдельная строка «Nikt nie wziął: 54,00 zł · na Tobie», если есть невзятое.

## Синхронизация без бэкенда

- Сессия хранится в `localStorage["splitcheck:session:<id>"]`.
- Изменения рассылаются через `BroadcastChannel("splitcheck:<id>")`, все вкладки применяют их к стору.
- Так 3 вкладки = 3 телефона на одном компьютере. Открыть ссылку во второй вкладке → это гость.
- Для принудительного вида гостя: `?as=guest` (создаёт нового участника в этой вкладке).
- **Dev-кнопка «Symuluj gości»** (видна только при `?dev=1`): добавляет 2–3 фейковых участников («Ania», «Kuba», «Ola»), которые с задержкой 400–900 мс тапают случайные позиции. Нужна для демо на одном экране.

Ограничение (честно): между разными реальными телефонами это не синхронизируется. Для этого позже — Supabase Realtime за тем же интерфейсом стора.

Сделать синхронизацию через интерфейс `SessionTransport` (`load`, `save`, `subscribe`), чтобы потом заменить на Supabase без изменений UI.

## Definition of done

- Хост: от главной до QR — не больше двух тапов (не считая съёмки).
- Гость: от открытия ссылки до своей суммы — без единого обязательного экрана до первого тапа.
- Сумма всех долей всегда равна итогу чека (тест + проверка в UI в dev-режиме).
- Все анимации на springs, никаких `ease`/`duration` для интерактивных элементов.
- Нет консольных ошибок, `tsc --noEmit` чистый.
